# Доступ к сервисам на адресе VPN-сервера

Форк сохраняет доступ через VPN к HTTPS и другим сервисам, расположенным на
публичном IP самого VPN-сервера. macOS направляет соединения процесса
Network Extension вне его туннеля; исключать весь адрес endpoint для всех
приложений не требуется.

В генераторе настроек на macOS автоматическое исключение endpoint отключено.
Явные `ExcludedIPs` пользователя продолжают действовать. Поведение iOS
сохранено. Основание — изменение WireGuard
`0340641c4c8d7be93e8f85be9827dec68711ab9a`.

## Проверка исходников

```sh
sh scripts/test-routing.sh
```

Скрипт компилирует настоящий генератор и его модели, проверяет маршруты IPv4,
IPv6, сохранение явных исключений, отсутствие общего маршрута и подмены DNS.
Go backend и рабочий VPN не запускаются. Временная сборка удаляется.

Для проверки воспроизведения ошибки передать исходную редакцию генератора:

```sh
sh scripts/test-routing.sh 9d5ee60edefa95b933a738dd7cda671dd18021fc
```

В этой редакции ожидается падение тестов доступа к endpoint.

## Сборка и установка на Mac

Использовать собственный Apple Developer Team ID и уникальный APP_ID_MACOS.
Xcode должен быть авторизован в этой команде. Для приложения и расширения
необходимы provisioning profiles с Network Extensions. Сборку без подписи
можно использовать для проверки компиляции; установка VPN требует подписи.

```sh
GOCACHE="$build_root/go-cache" GOMODCACHE="$build_root/go-modules" \
  xcodebuild -project WireGuard.xcodeproj -target WireGuardmacOS \
  -configuration Debug -jobs 2 -allowProvisioningUpdates \
  DEVELOPMENT_TEAM="$developer_team" APP_ID_MACOS="$app_id" \
  CODE_SIGN_STYLE=Automatic CODE_SIGN_IDENTITY='Apple Development' \
  ARCHS=arm64 ONLY_ACTIVE_ARCH=YES \
  SYMROOT="$build_root/products" OBJROOT="$build_root/objects" build
```

`build_root` — отдельный временный каталог; после установки удалить его.
Установить сборку из merged commit форка рядом с исходным приложением под
отдельным именем. Это сохраняет исходное приложение для отката. Не переносить
и не изменять ключи других профилей.

## Настройка почты Cogerent

1. Отключить прежний профиль с тем же peer.
2. Импортировать существующий конфиг в собранный клиент.
3. В копии профиля задать `AllowedIPs = 167.233.61.28/32` и убрать `DNS`.
   `Endpoint`, ключи и адрес клиента сохранить.
4. Подключить профиль и проверить свежий handshake.
5. Проверить `route -n get 167.233.61.28`: адрес должен идти через `utun`.
6. Проверить обычный HTTPS-запрос без `--interface` и прокси, затем страницу
   входа в Chrome по `https://webmail.cogerent.software/`.
7. Проверить маршрут к постороннему адресу, например `1.1.1.1`: он должен
   идти через обычное подключение. DNS и системные прокси не изменяются.

При изменении IP почты обновить точный маршрут после проверки DNS.
Откат: отключить профиль нового клиента и запустить исходный клиент.
Исходный полный профиль может направлять весь трафик через VPN; включать его
только если это разрешено пользователем.
